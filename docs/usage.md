# 使い方の詳細

`/design-to-code` を実行したあと、Claude が何を聞き、何を提示するかを 1 ステップずつ書いています。
全体像（工程と担当の一覧・なぜこの順番か）は [README の「仕組み」](../README.md)。

## 進み方

1. **何をもとに作るか**の確認（Figma URL / Claude Design / ラフ画 / 言葉）
   - Figma の場合: 対象フレームの特定 → デザイン情報の取得
   - ラフ画・言葉の場合: Claude がデザイン案（ブラウザで開ける HTML モック）を提示 → **納得するまで反復** → 合意後にコード化
2. **作るものの確定** — まず「ブラウザで見るもの（Web）か、アプリストアから入れるもの（ネイティブ）か」。Web ならさらに 3 つから選びます（「検索から人が来る？」「ページは増えていく？」の 2 問で決まります。判断がつかなければ 3 つを並べて見せます）:

   | | どんなページ向きか | 使う技術 |
   | --- | --- | --- |
   | **Web アプリ** | 検索から人は来ない。ログインして使う道具（管理画面・社内ツール） | React + Vite |
   | **LP** | 検索・SNS から人が来る。1 枚で完結する | Astro |
   | **コンテンツサイト** | 検索・SNS から人が来る。ページや記事が増えていく | Next.js |

   > **フレームワークを黙って決めることはしません。** 文脈から自明な場合も「〜と判断しました。理由は〜」と伝えるので、違っていればその場で変更できます
3. **Push 先リポジトリ**（URL・ブランチ・配置先）の確認 → 作業用のコピーを取得
4. **デザイントークン（色・余白などの単語帳）の確定**と、「どの値がどのトークンになったか」の対応表の提示（取り出し方は [`design-tokens.md`](design-tokens.md)）
5. ⚠️ **変換前診断（3 つの観点）** — **「どこが・何が問題か・どう直すか」を先に一覧で提示**します。Claude が勝手に埋めることはしません。「直してから再実行」か「この前提で進める」をあなたが選びます
   - **① 設定の不備** … トークン化されていない色や余白、Auto Layout でない配置、`Frame 12` のような名前
   - **② 設計の抜け** … hover / 無効 / エラー / 空っぽのときなど**描かれていない状態**、他の画面幅での振る舞い、長い文字が入ったとき
   - **③ 技術との不一致** … **Tailwind のスケールに乗らない余白**（例: 13px → 12px か 14px）、スケール外の角丸・文字サイズ、shadcn/ui の部品に当てはまらない UI。数値は**移植先にインストールされている Tailwind から実測**するので、バージョンが上がっても判定はずれません
6. **ここから先は Claude が実行します** — コード生成（Storybook ストーリーと CI ワークフローの雛形つき）→ **セルフチェック**（下記）→ 差分の確認 → **コミット・Push・Pull Request の作成**。トークンも同じ PR に入り、**GitHub の画面でファイルをアップロードする作業はありません**
7. Push 後、**Storybook は GitHub Actions が自動でビルド → GitHub Pages に公開**。以降は URL を開くだけで最新版を確認できます（詳細は [`testing-and-publishing.md`](testing-and-publishing.md)）

> ✅ **セルフチェックが効く場面** — 生成物が Airis 自身のルールに従えているかを機械的に検査し、**直せるものは Push 前に直し、判断が必要なものは報告**します。
> なかでも大きいのが **クラス名がトークンと一致しているか**（例: `text-muted` と書いたがトークンは `text-muted-foreground` だった）。**Tailwind はこの間違いをエラーにせず、ただ何も出力しません。** テストも全部通るので、放置すると「緑なのにスタイルが当たっていない」状態で世に出ます。
> ほかにストーリーの欠落・型エラー・import 漏れ・arbitrary value・ワークフローのパスずれなどを見ます。

## Airis 自体の動き

| 場面 | 動作 |
| --- | --- |
| Figma からの取得 | 公式 Dev Mode / Framelink の両対応（使える方を自動選択） |
| Claude Design 連携 | デザイン一式の受け渡し / `/design` コマンド。起点・途中確認・途中移行の 3 パターンに対応。受け取ったコードはそのまま使わず、ルール準拠で再生成 |
| 変換前診断 | コード化の前に Figma 側の問題（未トークン化の値・絶対配置・無名レイヤー・命名・未 Component 化・コントラスト等）を一覧化。**直し方を提示し、進め方はあなたが選ぶ** |
| Push | Push 先は毎回確認し、差分を提示してから実行。コミット・Push・PR 作成は Claude（`gh` 経由）。**Push 前のローカル検証はしない**（検査は GitHub Actions） |

## 主な Claude のコマンド

| コマンド | 役割 |
| --- | --- |
| `/setup` | 初回セットアップ（前提確認・作業ディレクトリ準備・任意の Figma 接続。冪等） |
| `/design-to-code` | デザイン確定 → コード化（Storybook 込み）→ Push |
